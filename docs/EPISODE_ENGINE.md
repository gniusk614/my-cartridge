# MY CARTRIDGE 에피소드 제작 엔진 1.3

## 제품 방향

MY CARTRIDGE는 고객의 인물·장소·사연을 게임에 입히는 고객 맞춤형 에피소드 게임이다. 개발 우선순위는 고객마다 코드를 수정하는 작업을 줄이고, 제작자가 맵·캐릭터·스토리를 편집해 검증·플레이·전달할 수 있게 만드는 것이다. 2026-11-10 사용자 지시에 따라 이 제작 기반을 우선한다.

공통 Godot 런타임은 이동·전투·상호작용·진행·저장을 담당한다. 고객별 게임팩은 장면, 맵, 등장인물, 기억, 편지와 PNG 에셋을 담는다. 스튜디오에서 만든 팩을 공통 런타임이 읽어 실행하므로 고객마다 게임 코드를 바꾸거나 Godot으로 다시 빌드할 필요가 없다.

## 시작하기

공개 제작 도구: https://gniusk614.github.io/my-cartridge/studio/

로컬에서는 저장소 루트에서 다음 명령으로 연다.

```bash
python3 -m http.server 8765 --bind 127.0.0.1 --directory web
# 브라우저: http://127.0.0.1:8765/studio/
```

1. **에피소드**에서 제목·팩 ID·개정 번호를 정한다. 고객마다 서로 다른 팩 ID를 사용한다.
2. **맵과 장면**에서 장면을 추가하고 테마·배경·시작점·출입구를 정한다. 박스·적·기억·발판·대화 인물을 버튼 한 번으로 배치하고 드래그한다. 선택한 박스는 썸네일이나 내 이미지로 바꾼다. [개체·에셋 편집 방법](ASSET_EDITOR.md)을 참조한다.
3. **캐릭터 공방**에서 캐릭터나 적을 고르고 전신 이미지를 넣는다. 복장·팔다리까지 바꾸고 7개 동작을 자동 생성해 적용한다. 기존 색상·얼굴 템플릿과 외부 시트도 사용할 수 있다. [전신 편집 방법](FULL_BODY_CHARACTERS.md)을 참조한다.
4. **스토리**에서 장면 도입·단서·회상·NPC 대화·마지막 편지를 작성한다.
5. **검증** 후 **플레이**로 실제 Godot 엔진에서 확인한다. **JSON 저장**으로 제작 원본을 보관하고 **게임 ZIP**으로 실행 파일까지 묶는다.

## 현재 구현된 제작 기능

| 영역 | 지원 내용 |
|---|---|
| 에피소드 | 고객별 ID·개정, 여러 프로젝트를 브라우저에 저장, JSON 가져오기·내보내기 |
| 장면 | 최대 8장면, 추가·삭제·순서 변경, 장면별 맵과 도입·기억·목표 |
| 맵 | 너비 640~1920, 거리·공원·노을 테마, 색상과 배경 이미지, 시작점·출입구·적·기억·발판·NPC 배치 |
| 개체·에셋 | 장식 박스 먼저 배치 후 그림 교체, 원본 기본 소품 5종, 여러 이미지 등록·재사용, 장면당 장식 64개, 복제·삭제·20단계 실행 취소 |
| 플레이 방식 | 전투와 기억 찾기 또는 전투 없는 탐색·이야기 장면 |
| 캐릭터 | 플레이어 1명·이야기의 상대 1명과 추가 NPC, 총 2~16명. 이름·외형·초상화·스프라이트 연결 |
| 도트 변환 | 로컬 PNG/JPEG/WebP → 32/48/64/96 픽셀 초상화, 8/16/32색 팔레트, 자르기, 모서리 배경색 제거, PNG 저장 |
| 전신 자동 동작 | 플레이어·적·NPC 전신 이미지 → 전체 그림 유지(기본)/사람형 부위 분할(고급) → 96×96 셀, 8열×7행. 7개 동작·원본·설정 보관, 경계/팔레트 조정·재생성·PNG 받기 |
| 공통 동작 | 32×48 셀, 8열×7행 시트. 대기·이동·공격·점프·앉기·피격·쓰러짐 템플릿과 애니메이션 메타데이터 생성 |
| ChatGPT 시트 | 참조 PNG·체형 보존 요청문 준비 → ChatGPT에서 직접 생성 → 4열·7행 PNG 가져오기 → 7개 동작 검수 후 인물/적 적용. [사용법](CHATGPT_SPRITES.md) |
| 외부 시트 | 동일 크기 셀 PNG를 등록하고 동작별 행·프레임 수·FPS 지정. 오른쪽을 기본으로 왼쪽은 반전 |
| 스토리 | 장면 도입·NPC 대화·기억·회상·엔딩 편지. `{{player}}`, `{{missing}}`, `{{캐릭터ID}}` 이름 치환 |
| 미리보기 | 부모 스튜디오와 같은 origin의 게임 프레임에 검증된 팩을 전달. 게임 코드는 실행하지 않고 데이터만 전달 |
| 전달 | 고객 팩·PNG 에셋을 포함한 JSON, 공통 Web 실행 파일을 포함한 독립 ZIP |

스프라이트시트를 외부에서 반드시 구할 필요는 없다. 내 전신 이미지로 동작을 생성하거나 내장 템플릿으로 시작할 수 있고, 사용 권한이 있는 완성 시트도 연결할 수 있다. 로컬 기본은 몸 전체를 유지하며, 사람형 컷아웃은 고급 옵션이다. 펭귄·동물의 새 자세는 ChatGPT 시트를 가져와 사용한다. 공유 시트 재생성은 선택한 인물만 분리해 바꾼다.

전신 동작 생성은 부위 회전·이동 방식이며 AI 재그림·새로운 자세나 가려진 신체 추론은 아니다. 경계가 겹치는 사진의 분할 자국은 미리보기에서 검수한다. 복잡한 배경 분할도 보장하지 않는다. 기존 초상화 픽셀화·얼굴을 붙이는 도형 템플릿은 별도 고급 설정으로 유지한다.

## 장면 진행과 저장

장면의 목표를 끝내고 출입구를 통해 공통 실내 편지방으로 들어간 뒤 책상에서 살피기를 누르면 다음 장면으로 이어진다. 마지막 장면에서는 엔딩 편지를 연다. 실내 편지방의 구조와 기본 음악은 현재 공통 템플릿이다.

저장은 기존 팩별 파일과 필드를 유지한다. `stage_id`는 현재 장면을 가리키고, 처치·기억·목표 ID는 에피소드 전체에서 유일해야 한다. 이전 장면의 사실은 유지하며 현재 장면 목표를 다시 계산한다. 불완전한 이전 장면이 있는데 뒤 장면을 가리키는 저장은 첫 미완료 장면으로 복구한다.

스키마 1.0.0의 세 샘플 팩도 계속 읽는다. 기존 1.1.0·1.2.0 에피소드도 계속 읽으며 새 팩은 1.3.0을 사용한다. 팩 개정이 다르면 이전 진행을 적용하지 않는 기존 정책도 유지한다. 유료 고객 팩의 개정·재배포 전에 명시적 마이그레이션·백업 정책이 필요하다.

## 로컬 보관과 고객 전달

스튜디오는 IndexedDB의 `my-cartridge-studio` → `projects`에 팩 ID별 초안과 변환 PNG를 저장한다. 입력 사진은 로컬에서 변환하며 서버로 보내지 않는다. 전신은 긴 변 최대 384픽셀의 PNG 원본도 초안·JSON·ZIP에 보관해 재생성에 사용한다. 일반 플레이 진행과 스튜디오 초안은 각각의 저장소를 사용한다. 미리보기 진행은 `user://studio_preview` 폴더에 격리하고 매 실행 새 진행으로 시작한다.

브라우저 데이터 삭제·사생활 보호 모드·용량 제한에 대비해 제작 원본은 JSON으로도 보관한다. JSON 저장과 미리보기는 초안 저장 완료를 기다린다. 게임 ZIP에는 공통 WASM·게임 팩·고객 `episode.json`·필수 정적 파일과 라이선스 고지가 들어간다. ZIP을 풀어 HTTP/HTTPS 호스팅에 올리면 해당 에피소드만 선택해 플레이할 수 있다. 파일을 `file://`로 직접 여는 방식은 지원하지 않는다.

고객 이름·사진·사연을 공개 Git 저장소나 공용 Pages에 자동 게시하지 않는다. 스튜디오에는 로그인·고객별 비공개 링크·접근 통제·업로드 서버를 구현하지 않았다. 생성된 고객 ZIP의 호스팅과 접근 권한은 배포자가 정해야 한다. 현재 공개 사이트는 공통 엔진과 제작 도구 및 가상 샘플만 제공한다.

## 구조

- `studio/core.js`: 프로젝트 기본값, 장면 생성, 스키마·참조·등장 조건 검사.
- `studio/assets.js` / `studio/presets.js`: 보관함·이미지 등록·역할별 연결·원본 기본 소품.
- `studio/ai_sprites.js` / `studio/ai_editor.js`: ChatGPT용 체형 보존 요청문, 참조 PNG, 격자 정리·7개 동작 검수·적용. 외부 API 호출 없음.
- `studio/body.js` / `studio/actor_editor.js`: 전신 실루엣·분할·7개 동작 생성, 캐릭터/적 공통 편집기.
- `studio/pixel.js`: 로컬 팔레트 변환·배경색 처리·동작 템플릿 PNG 생성.
- `studio/studio.js`: 제작 폼·맵 배치·IndexedDB 초안·미리보기·파일 전달.
- `studio/zip.js`: 실행 파일의 CRC를 포함한 ZIP 생성.
- `game/scripts/data/asset_library.gd`: 검증한 PNG 디코드·텍스처·시트 프레임 렌더링.
- `pack_loader.gd` / `pack_validator.gd`: 파일 경로·코드 대신 허용된 데이터만 등록·검증.
- `game_session.gd` / `quest_manager.gd`: 장면 진행·이름 치환·사실 기반 목표와 저장 복원.
- `stage.gd`: 기존 샘플 맵과 데이터 기반 맞춤 맵.
- `tools/prepare_web.py`: 제작 도구·스키마·게임을 함께 배포하고 JS/CSS 의존성의 해시 파일명을 생성.

## 검증 범위와 다음 확장

Godot 검사에 두 맞춤 맵·외부 PNG 스프라이트·초상화·NPC 대화·평화로운 장면·다음 장면·다중 장면 저장 복원과 잘못된 참조·시트 범위를 추가했다. 브라우저 검사는 실제 이미지 변환 → 동작 생성 → JSON 저장·재불러오기 → 게임 적용, 두 맵의 스토리 완주, ZIP 추출·별도 HTTP 서버에서 고객 팩 자동 실행을 검사한다. 전신 생성·플레이어/적 적용·공유 시트 분리·전신 원본 보존·실행 취소·작은 터치 화면도 검사한다. 기존 모바일·전투·저장 회귀도 유지한다.

후속 제작 엔진 우선순위는 다음과 같다.

1. 제작자가 실제 고객 에피소드를 만들어 보며 필요한 편집 흐름·공통 템플릿을 보강.
2. 에셋 제작 확장: 선택형 AI 스타일 재그림, 인물 일관성·동작별 품질 검수, 아트 템플릿 라이브러리.
3. 맵·스토리 확장: 실내 템플릿 편집, 타일셋, 대화 분기·이벤트 그래프, 추가 퀘스트 유형.
4. 전달 운영: 고객별 비공개 호스팅·접근 권한, 제작 버전 관리·백업·저장 마이그레이션.

온라인 협동·결제·임의 장르를 만드는 범용 엔진은 현재 범위에 넣지 않았다. Godot 위에 고객 맞춤형 액션·탐색 에피소드를 제작하는 기반을 구축한 단계다. iPhone/Android 실기기의 성능·조작감·노치·OS 인터럽트는 별도 검증 대상이다.
