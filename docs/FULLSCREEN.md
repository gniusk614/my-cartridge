# 모바일 가로 화면과 전체화면

모바일에서 게임이 작은 16:9 영역에만 표시되던 문제를 수정했다. 시작 페이지에서 `가로 전체화면으로 시작`을 누르면 사용자 제스처 안에서 Fullscreen API를 호출하고, 성공 후 가로 방향 잠금을 요청한다. 브라우저가 거부해도 현재 화면에서 계속할 수 있고, 지원하는 환경에서는 화면 위의 전체화면 버튼으로 재시도할 수 있다.

Godot의 화면 확대 모드를 keep에서 expand로 바꿨다. 기준 해상도는 320×180으로 유지하되, 긴 가로 화면에서는 좌우 시야가 늘어나고 더 높은 화면에서는 배경이 아래까지 이어진다. 카메라 경계와 중앙 팝업, 화면 양쪽 터치 버튼도 실제 뷰포트 크기에 맞춰 다시 배치한다. 웹에서 전달받은 safe-area inset을 반영해 노치와 홈 제스처 영역을 피한다.

세로 화면에서는 기기를 가로로 돌리라는 안내를 표시한다. 플레이 중 세로로 바꾸면 안내 뒤에서 적이 공격하지 않도록 게임을 일시정지한다. 가로로 돌아오면 게임의 일시정지 화면에서 계속할 수 있다.

## iPhone에서 주소줄 없이 실행

iPhone Safari에서는 일반 게임 요소의 Fullscreen API와 가로 방향 잠금에 제약이 있다. API가 실제로 활성화되어 있는지 확인하고, 지원하지 않는 경우 홈 화면 실행 경로를 안내한다.

1. Safari에서 게임 주소를 연다.
2. 공유 메뉴에서 `홈 화면에 추가`를 선택한다.
3. 추가한 MY CARTRIDGE 아이콘으로 실행하고 기기를 가로로 돌린다.
4. 세로 방향 잠금이 켜져 있다면 해제한다.

홈 화면 메타데이터와 웹 앱 manifest에 fullscreen/standalone 표시 및 가로 방향 선호를 지정했다. 브라우저의 정책을 우회하지 않으며 iOS 버전별 실제 표시와 방향 고정은 실기기에서 확인해야 한다. 오프라인 실행을 제공하는 service worker는 추가하지 않았다.

## 검증

- Godot 자동 검사 91개, 기존 10회 완주 통과. 실제 창을 1950×900으로 바꿔 뷰포트 확장·버튼 경계·팝업 중앙·카메라 양 끝을 확인했다.
- Node 웹 셸 검사 8개 통과. 전체화면 호출 순서, 미지원·비활성 API·거부 처리, 현재 화면 시작, 홈 화면 실행, 로딩 실패, 세로 전환 일시정지 알림을 검사했다.
- 로컬 브라우저에서 시작 버튼, 전체화면 전환과 복귀, 게임 로딩·이동을 확인했다. 최종 iPhone·Android 동시 터치와 실제 시스템 UI 표시는 기기 확인이 필요하다.

게임 팩 파일과 웹 셸 JS/CSS에는 콘텐츠 해시가 들어간 파일 이름을 사용해 이전 배포의 화면 코드가 캐시에 섞이지 않도록 했다.
