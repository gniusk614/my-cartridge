# 모바일 UX 개선 기록 (2026-11-10)

기존 전투·스토리·저장 형식과 세 샘플 팩을 유지하며 모바일 입력과 웹 화면만 개선했다. 이동은 기존 지면 x/y 벡터에 아날로그 입력을 더하고 길이를 1 이하로 제한한다. 적 AI, 전투 타이밍·공격 중 정지·점프 높이, 단서·카페·엔딩, 저장 데이터·개정은 바꾸지 않았다.

## 플로팅 조이스틱

`game/scripts/ui/mobile_controls.gd`가 화면 왼쪽 아래 영역(상단 HUD 아래, 화면 너비 48%까지)의 첫 터치를 소유한다. 터치한 지점을 원점으로 고정하며 다른 손가락은 원점을 빼앗지 않는다. 손가락이 활성 영역 밖으로 나가도 해당 터치의 이동·해제를 계속 받는다.

기본 반경은 논리 24px이다. 반경의 16%까지는 벡터가 0이고, 바깥은 `(기울기 - 0.16) / 0.84`로 0부터 1까지 선형 보간한다. 대각선을 포함한 모든 방향을 유지하며 반경을 넘기면 최대 속도에 제한한다. 방향키용 Input 액션에 아날로그 값을 쓰지 않고 `MobileInput.movement`에 별도로 보관하므로 조이스틱 해제가 WASD를 해제하지 않는다. 기존 플레이어 최대 속도 80은 유지한다.

소유 터치의 해제·취소 즉시 벡터를 0으로 만들고 다음 물리 프레임부터 이동이 멈춘다. 관성 보간은 없다. 피격 넉백이나 공격 중 정지 같은 기존 전투 규칙은 유지한다. 모달·일시정지·포커스 손실·레이아웃 변경·노드 제거에서도 입력을 초기화한다. 돌아온 뒤에는 새 터치가 필요하다.

## 액션 버튼

오른쪽 아래에는 공격(반경 20), 그 위 점프(15), 왼쪽 위 살피기(15)의 원형 영역을 부채꼴로 배치한다. 원형 그리기와 원형 히트 영역이 일치한다. 키보드 K/Ctrl 앉기는 유지하고 모바일 앉기 버튼과 방향 화살표는 제거했다.

각 포인터는 처음 누른 버튼을 해제까지 소유한다. 같은 버튼을 여러 손가락으로 누르면 마지막 손가락이 떨어질 때 해제한다. 다른 손가락이 움직이거나 떨어져도 조이스틱과 액션의 소유권을 유지한다. 따라서 이동+점프+공격을 동시에 입력할 수 있다. 액션 버튼은 기존 Input 액션에 연결되며 공격 연타·연계 규칙은 같다. 데스크톱에서는 마우스로도 원형 컨트롤을 조작할 수 있다.

UI는 논리 뷰포트 크기와 safe-area를 반영한다. 더 높은 논리 뷰포트에서는 컨트롤을 최대 1.4배 확대하고, 방향 전환 시 잡고 있던 입력을 해제해 좌표 변경으로 인한 오작동을 방지한다.

## 가로 화면

시작 터치에서 전체화면 → 가로 잠금을 순서대로 시도한다. API가 없거나 거부되어도 플레이를 시작한다. 세로 뷰포트에서는 캔버스를 90도 회전하고 backing 크기·터치 역변환·안전영역의 축을 함께 교환한다. 기존 회전 요청 안내와 방향 변경 강제 일시정지는 제거했다. 세부 구현·브라우저 제약은 [FULLSCREEN.md](FULLSCREEN.md)에 정리했다.

페이지 코드는 OS나 Safari 주소줄을 강제로 회전·숨길 수 없다. CSS 대체 화면은 콘텐츠만 회전한다. 실제 iPhone Safari와 Android Chrome에서 API 성공·시스템 UI·조작감 확인이 필요하다.

Godot 추가 검사는 실제 `InputEventScreenTouch`/`InputEventScreenDrag`를 뷰포트에 전달한다. 원점·데드존·절반 기울기의 실제 40px/s 이동·비정축 방향과 크기 제한, 소유권, 점프+공격+이동, 독립 해제·touchcancel, 같은 버튼의 다중 접촉, 일시정지·포커스·리사이즈 초기화, 키보드 입력 보존, 원형 바깥 거부를 검사한다. 이전 화면 경계 검사는 새 원형 버튼의 실제 반경으로 갱신했다.

Node 검사는 전체화면 제스처와 순서·거부·미지원·standalone·로딩 실패를 유지하고, DPR·안전영역 축 교환·차단 안내 제거·좌표 역변환·멀티터치 ID와 cancel·마우스·HTML 전체화면 버튼 입력을 확인한다.

Chrome은 844×390 및 390×844, DPR 2에서 모두 1688×780 backing으로 렌더링했다. 픽셀 화면을 직접 확인해 조이스틱과 원형 액션 표시, 공중 공격, 해제 후 기본 표시와 지상 복귀를 확인했다. 소프트웨어 WebGL의 ReadPixels 성능 경고가 있어 FPS나 GPU 성능 결과로 사용하지 않았다.

WebKit 검사는 macOS의 Playwright WebKit으로 수행했으며 iPhone Safari 실기기 검증이 아니다. Chrome의 CDP 멀티터치와 달리 WebKit 다중 터치는 DOM 이벤트로 주입했고 메뉴 탭은 브라우저 터치 API로 수행했다.

실기기 iPhone Safari·Android Chrome의 터치 감각·노치·주소줄·오디오·앱 복귀·브라우저 재시작 저장 지속성은 미검증이며, 이 자동 검사 결과로 통과 처리하지 않는다.
