# MY CARTRIDGE 고객 맞춤형 에피소드 제작 엔진

사연을 전투와 기억 수집으로 풀어내는 선물 게임의 Godot 기술 시제품입니다. 카페 거리에서 적을 물리치고 단서를 읽은 뒤, 오른쪽 카페에 들어가 책상 앞에서 편지를 읽습니다. 상자에서 점프해 난간 위를 탐색할 수도 있습니다. 2026년 11월 12일 구현본입니다.

## 생일 액션 에피소드

**[〈너에게로 가는 길〉 예제로 시작](https://gniusk614.github.io/my-cartridge/studio/?template=birthday)** — 아기를 안고 남편과 함께 길을 걸으며 바이러스·큰 그림자를 물리치고 사진 조각 6개를 모읍니다. 마지막에 사진 속 아이의 정체와 생일 편지를 공개합니다. 실제 이름·가족 사진은 넣지 않은 교체용 템플릿입니다. 스튜디오에서 아내의 아기 시절 사진과 현재 가족 사진을 넣어 완성하세요. [스토리·이벤트·사진 교체 사용법](docs/BIRTHDAY_EPISODE.md)

## 에피소드 만들기

**[에피소드 스튜디오 열기](https://gniusk614.github.io/my-cartridge/studio/)** — 맵·캐릭터·스토리를 브라우저에서 편집하고 실제 게임으로 미리 봅니다. 플레이어·적·NPC의 전신 이미지로 옷·팔·다리·신발까지 바꾸고 7종 동작 스프라이트시트를 자동 생성합니다. 동물의 몸을 나누지 않는 기본 움직임·사람형 컷아웃·기존 얼굴 템플릿·외부 PNG 시트를 지원하며 외부 시트는 필수가 아닙니다. [전신 캐릭터·적 사용법](docs/FULL_BODY_CHARACTERS.md)

**ChatGPT로 동작 만들기:** 캐릭터·적을 고른 뒤 참조 PNG와 생성 요청문을 받습니다. ChatGPT에 첨부해 4열·7행 PNG를 만들고, 스튜디오에 가져와 7개 동작을 확인한 뒤 적용합니다. 별도 API 연결은 사용하지 않습니다. [펭귄·동물과 ChatGPT 시트 사용법](docs/CHATGPT_SPRITES.md)

**개체 배치:** 맵에서 `＋ 장식 박스`를 누른 뒤 썸네일이나 내 이미지를 선택하면 위치·크기를 유지하며 그림만 바뀝니다. 기억·대화·적·발판도 한 번 클릭으로 추가하고, 복제·삭제·실행 취소를 지원합니다. 에셋 보관함에서 이미지를 등록해 장식·배경·초상화·동작 시트로 재사용할 수 있습니다. [개체·에셋 사용법](docs/ASSET_EDITOR.md)

최대 8장면을 연결하고 전투 없는 이야기 장면도 만들 수 있습니다. 제작 원본은 JSON으로, 공통 실행 파일과 고객 에피소드는 게임 ZIP으로 내보냅니다. 이미지는 서버로 보내지 않고 초안·변환 PNG·축소한 전신 원본은 브라우저 IndexedDB에 저장하며 JSON·ZIP에도 포함합니다. 고객 데이터를 공개 저장소에 자동 게시하지 않습니다.

로컬 기본 움직임은 원본 전체를 유지하고, 사람형 부위 분할은 고급 옵션으로 제공합니다. 가려진 신체나 새로운 시점을 AI로 그리지는 않습니다. 제작 순서·지원 범위·확장 계획은 [docs/EPISODE_ENGINE.md](docs/EPISODE_ENGINE.md)를 참조하세요.

## 바로 실행

**휴대폰에서 플레이:** https://gniusk614.github.io/my-cartridge/ 를 열고 `게임 시작`을 누릅니다. 시작 터치로 전체화면과 가로 방향 잠금을 시도하며, 지원되지 않는 세로 화면에서는 게임 화면을 90도 회전해 가로 비율로 표시합니다. 왼쪽 아래 영역을 터치한 지점에서 조이스틱을 밀어 이동하고 오른쪽 공격·점프·살피기 원형 버튼을 사용합니다. iPhone은 Safari의 `공유 → 홈 화면에 추가`로 주소줄 없이 실행할 수 있습니다.

macOS에서 `실행.command`를 열거나 다음 명령을 실행합니다. 이 작업 공간에서 받은 공식 Godot 4.7.2 엔진을 자동으로 찾습니다. 다른 컴퓨터에서는 Godot 4.7.2를 설치하고 `game/project.godot`를 열어 F6 대신 **F5 프로젝트 실행**을 누르세요.

```bash
bash tools/godot.sh
```

엔진을 직접 지정할 수도 있습니다.

```bash
GODOT_BIN=/Applications/Godot.app/Contents/MacOS/Godot bash tools/godot.sh
```

| 조작 | 키보드 | 화면 버튼 |
|---|---|---|
| 이동 | WASD 또는 방향키 | 플로팅 아날로그 조이스틱 |
| 공격과 3타 연계 | J 반복 입력 | 공격 |
| 점프 | Space | 점프 |
| 앉기와 느린 이동 | K 또는 Ctrl 누르고 있기 | 키보드 전용 |
| 단서·출입·편지 | 근처에서 E | 살피기 |
| 일시정지 | Esc | 오른쪽 위 Ⅱ |

팩을 고르고 `시작 / 이어하기`를 누릅니다. `새로 시작`은 선택한 팩의 진행을 새로 시작합니다. 적을 모두 물리친 다음 빛나는 단서를 찾으세요. 오른쪽 카페 문에서 E로 들어가고 창가 책상에서 E로 편지를 읽습니다. 내부 아래쪽 문에서 E를 누르면 거리로 돌아갑니다. 단서를 모으기 전에도 카페를 둘러볼 수 있습니다.

거리 중간의 상자와 난간은 위쪽 길(y 104~121)에 있습니다. 상자 왼쪽에서 위쪽 길로 맞춘 뒤 오른쪽으로 점프해 상자 위에 착지하고, 다시 오른쪽으로 점프하면 난간에 올라갑니다. 난간은 지면에서 한 번의 점프로 닿지 않는 높이입니다. 난간 위를 걷거나 아래 방향으로 걸어 내려올 수 있습니다. 앉기는 자세와 이동 속도를 바꾸며 무적·회피 효과를 주지 않습니다.

## 들어 있는 기능

- 320×180 기준의 가변 화면 확장, Compatibility 렌더러, nearest 픽셀 표현, 가로 스크롤과 상하 깊이 이동. 가로 전체화면 시작·노치 안전영역·세로 화면 회전 대체.
- 360도 플로팅 조이스틱, 기울기별 속도·16% 원형 데드존·해제 즉시 입력 정지. 큰 공격 버튼과 점프·살피기 부채꼴 배치, 이동+점프+공격 동시 터치.
- 3타 연계, 활성 프레임 Area2D 공격 판정, 공격별 중복 타격 방지, 방향·깊이 검사, 피격·넉백·무적 시간.
- 독립 높이축 점프와 중력, 상자·난간 착지와 높은 발판의 측면 충돌, 높이 차이를 반영한 타격 검사, 앉기·느린 이동.
- 일반 적과 느리고 체력이 높은 적, 데이터 기반 등장 위치·접근 트리거·순차 등장.
- 처치 → 단서 생성 → 상호작용 → 회상 → 출구 → 편지와 오리지널 임시 음악.
- 카페 내부 출입, 실내외 경계·카메라 전환, 외부 적 정지·복원, 단서 수집 이후 내부 편지 엔딩.
- 팩별 로컬 저장, 중복 수집 방지, 사망 후 기억과 처치 기록 유지, 일시정지·기억 앨범.
- 스키마와 ID 참조·의존 순환·달성 불가능 목표 검사. 팩에 파일 경로나 코드를 넣지 않습니다.
- 같은 실행 코드로 세 샘플 팩을 선택해 플레이. 적 구성·등장 의존성과 단서 위치에 차이가 있습니다.

## 웹 빌드

`web`에 실행 가능한 싱글 스레드 웹 내보내기가 있습니다. `index.html`을 파일로 직접 열면 WebAssembly 로딩이 실패하므로 HTTP 서버를 사용하세요.

```bash
python3 -m http.server 8765 --bind 127.0.0.1 --directory web
```

브라우저에서 `http://127.0.0.1:8765`로 접속합니다. 재빌드에는 같은 버전의 Godot Web export templates가 필요합니다.

```bash
mkdir -p build/web
bash tools/godot.sh --headless --export-release Web ../build/web/index.html
python3 tools/prepare_web.py
```

## 검증 명령

```bash
bash tools/godot.sh --headless --editor --import --quit
bash tools/godot.sh --headless --fixed-fps 60 --script res://tests/test_runner.gd
python3 tools/check_content.py  # jsonschema 패키지 필요
npm run test:unit
# 브라우저 검사 최초 설치 후 실행
npm ci
npx playwright install chromium webkit
npm run test:browser
```

테스트는 전용 `user://mc_automated_tests` 폴더만 사용합니다. 게임의 일반 저장 폴더를 덮어쓰지 않습니다. 봇 완주는 실제 이동 입력, 물리 프레임, Area2D 판정, 적 AI, 단서 상호작용을 통과합니다. Godot 176개·웹 셸/스튜디오 단위 48개·브라우저 36개 검사와 기존 봇 완주 10회를 통과했습니다. Chromium·WebKit의 가로·회전 대체 화면에서 3점 동시 터치와 숨김 후 복귀, 실제 전투 진행의 IndexedDB 저장·새로고침·브라우저 재시작 복원을 검사합니다. 자동 검사는 재미·터치 조작감·실기기 성능을 보증하지 않습니다.

## 데이터 수정

고객 에피소드는 스튜디오에서 편집하고 JSON으로 가져오거나 내보냅니다. 새 고객 팩을 추가할 때 소스 코드를 수정할 필요가 없습니다.

기본 샘플을 직접 수정할 경우 `schemas/game_pack.schema.json`이 정규 스키마이며 `examples/*.json`이 편집 기준 샘플입니다. 수정 후 각각 `game/content`의 동일 이름 파일에도 복사하고 `check_content.py`와 Godot 검사를 실행합니다. 지원 팩 ID는 `pack_loader.gd`의 허용 목록에 등록합니다. `docs/DATA_CONTRACT.md`에 필드와 진행 복원 규칙을 설명했습니다.

## 남은 작업

이 빌드는 원문 P0의 시작점입니다. 플레이 분량 2~4분, 타격감에 대한 사람의 평가, iPhone Safari·Android Chrome의 동시 터치·음향·복귀·저장 유지 테스트는 미통과 상태입니다. 기본 전투 아트와 음원은 임시 템플릿입니다. 다중 장면·고객별 맵·캐릭터·스토리·개체·에셋 편집과 전신 이미지·자동 동작 생성과 1.4 스토리 이벤트·생일 반전 템플릿을 제공합니다. 최종 이미지별 애니메이션 품질 검수는 필요합니다. 회복 소품·회피·온라인 협동·플랫폼·결제·AI 재그림·새 자세 추론은 아직 구현하지 않았습니다.

웹 저장은 브라우저 데이터 삭제나 사생활 보호 모드에서 유지되지 않을 수 있습니다. 저장 개정이 달라지면 이 버전은 새 진행으로 시작합니다. 개정 간 마이그레이션은 팩 배포 전에 추가해야 합니다.

제작 엔진의 다음 작업은 `docs/EPISODE_ENGINE.md`, 모바일 테스트와 배포 방법은 `docs/DEVELOPMENT.md`, 모바일 입력 설계는 `docs/MOBILE_UX.md`, 전체화면 동작은 `docs/FULLSCREEN.md`, 브라우저 회귀·저장 복원 검사는 `docs/BROWSER_TESTS.md`, 초기 검증 기록은 `docs/VALIDATION.md`에서 확인합니다.
